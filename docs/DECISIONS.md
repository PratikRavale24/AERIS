# AERIS Decisions Log

All design decisions and trade-offs are recorded here.

## Phase 0 — Scaffold & Infrastructure

| # | Decision | Rationale |
|---|----------|-----------|
| D-001 | Use `psycopg2-binary` for sync + `asyncpg` for async DB connections | Alembic requires sync; FastAPI benefits from async. Binary package avoids build-time libpq dependency. |
| D-002 | Two Docker networks: `edge` (bridge) and `internal` (internal: true) | Concrete air-gap proof — backend and DB have no outbound internet access. Only nginx is on the edge network. |
| D-003 | Secrets via Docker secrets (mounted at /run/secrets) | More secure than environment variables; not visible in `docker inspect` or process listing. |
| D-004 | Self-signed TLS cert generated by script | No external CA dependency; documented as a limitation for production deployment. |
| D-005 | nginx unprivileged image | Runs as non-root (UID 101), no capability escalation needed. |
| D-006 | Postgres init.sql uses `\set` + `cat` for passwords | Docker Postgres image supports reading from secrets files this way; avoids passwords in SQL files. |
| D-007 | `protect_immutable_tables()` called after migration rather than in init.sql | Tables don't exist during init.sql execution; must be called after Alembic creates them. |
| D-008 | APP_NAME in single constant in config.py | Allows renaming the entire application by changing one value. |
